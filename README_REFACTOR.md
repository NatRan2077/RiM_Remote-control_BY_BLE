индикации не менялась — проверено пословным сравнением кода (diff без
учёта комментариев даёт только перечисленные ниже правки).

## Что осталось за рамками (следующие шаги)

1. `app_ble.c` не экспортирует заголовок: `g_need_connect`, `g_target_addr`,
   `bleDevCnt`, `bleDevList`, `g_connecting` объявляются `extern` по месту.
   Стоит завести `app_ble.h` с публичным API.
2. Кодировки: часть файлов CP1251, часть UTF-8. Стоит привести всё к UTF-8
   (ARMCC 5 компилирует UTF-8 комментарии; строки для ЖКИ уже записаны
   байтовыми эскейпами и от кодировки файла не зависят).
3. Bootloader содержит расходящиеся копии `lcd.c`, `memory.c`, CMSIS —
   вынести общий код в отдельный каталог, подключаемый обоими проектами.

## Проверка после сборки

1. Проект собирается без новых предупреждений.
2. Смоук-тест: скан → выбор БУ → подключение → серийник на экране →
   ВКЛ/ОТКЛ с подтверждением → телеметрия обновляется каждые 2 с.
3. В Tera Term видны `[RIM TX]/[RIM RX]`; строка `[BLE RX] overflow`
   появляться не должна.
4. Обмен по USB (DLMS-маршрутизация) не затронут — `threads_DataRouting.c`
   буферы BLE-транспорта не использует.

## Правки интерфейса (v2)

Ограничение железа: текстовая зона ЖКИ — ровно 6 знакомест, поэтому длинные
надписи заменены ближайшими по смыслу, влезающими на экран.

| Было | Стало | Примечание |
|------|-------|-----------|
| `СЧЕТ` | `СЧ.ВО` | «СЧЕТ.ВО» — 7 знаков, не помещается. В шрифт добавлен символ точки |
| `КОЛ У<n>` | `УСТР<nn>` | Две цифры, до 99 устройств (раньше при 10+ показывалось «9»). «УСТР. 00» с точкой и пробелом — 8 знаков, не помещается |
| `Err0r` | `Error` | В цифровой шрифт добавлена строчная `o` (CHAR_o), не путается с нулём |
| `1` / `0` после команды | `ОТПР.` → `УСПЕХ` / `ОШИБКА` | «ОТПРАВКА» и «УСПЕШНО» — 8 и 7 знаков; при желании тексты меняются в константах `TXT_SENDING` / `TXT_SEND_OK` / `TXT_SEND_ERR` |

Логика индикации отправки (вместо флагов `ackShow/ackOk` — конечный автомат
`sendState`):

- нажатие ПРАВОЙ кнопки → на 1-6 надпись `ОТПР.`;
- пришло подтверждение → `УСПЕХ` (3 с), при отказе → `ОШИБКА` + код отказа
  на 8-15;
- **нет ответа 3 с → `ОШИБКА`** (раньше пульт молча ждал бесконечно);
- пункт `СЧ.ВО` теперь всегда показывает локальный счётчик — сброс виден
  по надписи `УСПЕХ` и обнулению значения, без сбивающих с толку «1» и «0»;
- при отсутствии аварии разряды 8-15 пустые (раньше горел «0»).

Дополнительно изменены: `User/lcd.c` (глифы `.` и `CHAR_o`),
`User/inc/lcd.h` (значение `CHAR_o = 242`).


## Хотфикс сборки (Undefined symbol `dlms`)

`thread_dataRequest.c` держал не только буферы BLE, но и определение живой
глобальной переменной `dlms_t dlms;` (её `extern`-объявление — в
`dlmsListObj.h`, пользуются 7 файлов: thread_main, cosem, dlms, dlmsListObj,
threads_other и др.). При удалении модуля определение пропало → линкер
L6218E: Undefined symbol dlms.

Исправление: `dlms_t dlms;` перенесён в `User/dlmsListObj.c` — парный .c
к заголовку с extern-объявлением. Полная проверка показала, что это был
единственный «живой» символ из удалённого модуля; остальные (буферы BLE,
Check_HDLC_Frame, parsingDlms, dataRequest_pt) в активном коде больше не
используются.
